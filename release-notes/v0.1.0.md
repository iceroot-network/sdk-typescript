The first release. The interfaces below changed shortly before it; code written against earlier development builds needs these changes.

- **No fee from the node's statistics.** `Draft.build(chain, request, facts)` takes no fee statistics any more, the builders of `net.build` never read `/node/fees`, and `FeeSource` is `"floor"`, `"explicit"` or `"unverified"` (the `"node-statistics"` source is gone). `net.fees.statistics()` stays, for display. A serialized draft whose fee source names anything other than `"floor"` or `"unverified"` reads as `"explicit"`.
- **A serialized draft's floor is the floor only on the reader's own connection.** `FeeSource` gains `"unverified"`. `Draft.deserialize(bytes, profile)` computes the floor under the network configuration the bytes carry, whose fee table the pinned network hash does not cover, so a fee the bytes call the floor and that equals that floor now reads `"unverified"` instead of `"floor"`, and `summary.fee.floor` is for display only: never show "network minimum" for it. `Draft.deserialize(bytes, net)`, with a network `connect` returned, reads the draft on that connection's chain at the network's next block (`net.nextHeight`): it reads `"floor"` when the fee is the floor at the draft's height and the floor at the network's next block is the same, `"unverified"` when a change of the fee table lies between the two heights (the draft's height is its builder's choice), and refuses a draft built under another network configuration with `NetworkMismatch` (`details.reason`: `"configuration"`); the Tauri entry does the same through the plugin. Code that handles every `FeeSource` needs the new value.
- **No floor without an enabled fee table.** Where the milestone in force has no enabled dynamic fee table, the node's pool applies settings of its own, so there is no floor: `rules.fees.floorAvailable` is `false` (it now says whether the floor is in force at that height), `draft.summary.fee.floor` is absent, and fee `"minimum"` and `{ multiplierBasisPoints }` throw `FeeUnavailable`. Such a network needs an exact `bigint` fee. A draft never carries a zero fee labelled as the floor.
- **Headers for a relay behind a proxy.** `connect(profile, { headers })` sends extra headers with every request, for a relay that asks for a token. The Rust SDK of the same version adds the same to its HTTP client (`HttpOptions::headers`), so a Rust backend reaches the same relay. A header name must be an HTTP token and a value visible ASCII text; `connect` refuses anything else with `InvalidArgument`, without showing the value.
- **No redirects.** The SDK asks its transport not to follow redirects (`redirect: "manual"`, and `maxRedirections: 0` for the Tauri HTTP plugin's `fetch`), and a relay that answers with one is skipped like a relay that cannot be reached, so headers and submissions reach the listed relays only. A custom transport that follows redirects anyway defeats this.
- **Bounds of `connect`'s numbers.** `timeoutMs` and `rateLimit.windowMs` are at most 2^31 - 1 milliseconds, and `rateLimit.requests` at most 2^32 - 1; a larger value is `InvalidArgument`. (On the WebAssembly entry a larger timeout used to fire at once, and 2^32 requests left no allowance at all.)
- **Messages are text, and never a proof.** `Messages.sign` refuses with `InvalidArgument` a message given as bytes that are not UTF-8 text (every transaction begins with the byte 0xff, which text never contains), and text whose first line is an ownership proof's: an account imported from a Solar passphrase has the Solar key, and proofs are made only by `OwnershipProof.sign` and `OwnershipProof.fromSignature`. `Messages.verify` returns false for bytes that are not text.
- **`SignIn.sign(account, message, { origin, now })`.** A wallet signs a website's sign-in message with it: the message is checked against the asking page's origin and the account's own public key and address where the key signs, in the module or in the Tauri plugin (`key_sign_sign_in`), and signed only if every check passes; a challenge a page of another origin relays, one made for another account and a lapsed one are refused with `InvalidSignIn`. It replaces `SignIn.parse` followed by `Messages.sign`, which a wallet no longer uses for a sign-in. The example wallet and the browser wallet guide sign in this way.
- **`net.watch`.** Stopping a watch, by the function it returns or by its `signal`, now also removes its listener from that signal. The documentation states its limits: one `block` event per poll for the latest block, and at most 50 new transactions per poll for the watched address.
- **The height follows the node's status on both entries.** `net.height` and the rules of the next block follow a status read (`net.node.status()`, and the builders' own read) down as well as up, so an answer's `X-Block-Height` far ahead holds them only until the next status. The Tauri entry now does what the WebAssembly entry did.
- **Answer limits whatever the transport gives.** The WebAssembly entry's transport reads an answer in chunks from any async iterable body (such as the Node.js stream of `node-fetch`), not only from a web stream, and stops once more than 8 MiB has arrived; it refuses an answer whose `content-length` says it is larger before reading any of it, also when a transport joined the header's values. Only a response with no body to read in chunks is read whole before its size is checked.

It also carries the vote selection library, the keystore, ownership proofs and an example wallet:

- **`@iceroot-network/sdk/vote`**: select a vote in four modes (Diversity, Reliability, Maximum Rewards, Support Newcomers), sampled per account and reproducible, then `split`, `check` and `validateVote`; `VoteSnapshot.fromNode` builds the snapshot from the node client. Validators a node refuses votes for are left out.
- **`@iceroot-network/sdk/keystore`**: `encrypt`, `decrypt`, `inspect`, `changePassword` and `reencrypt` for a versioned encrypted format of recovery-phrase entropy (Argon2id and XChaCha20-Poly1305), with presets for desktop, mobile and web. Password bytes are wiped after use.
- **`@iceroot-network/sdk/ownership`**: build, sign and verify version 1 ownership proofs of Solar addresses, as the legacy signer makes them, for claims.
- **`Keys.fromKeystore` and `net.keys.fromKeystore`**: an account opened straight from a keystore, decrypted and derived inside the SDK, so the phrase never reaches JavaScript.
- **`@iceroot-network/sdk/tauri`** (with `/tauri/vote`, `/tauri/keystore` and `/tauri/ownership`): the same interface for Tauri apps, backed by the Rust SDK's plugin `tauri-plugin-iceroot` of the same version. Keys, signing, the keystore and every request to the node run in the plugin; the page loads no WebAssembly and needs no content security policy change. The calls that compute return promises, so an app written with `await` on every SDK call runs on either entry, and `init()` checks that the plugin is of the package's release. What differs through the plugin (the details of transport errors, `net.watch` with an invalid address, proxies) is listed in the Tauri quickstart, step 4. Checked on Linux with the SDK's test suites and the devnet scenario; the plugin builds for Android, and macOS and iOS builds need a Mac.
- **Reading a phrase back in a Tauri app is a permission of its own.** The plugin's `iceroot:default` leaves out `keystore_decrypt`, the one command that hands a recovery phrase to the page: an app with a screen that shows the phrase again grants `iceroot:allow-keystore-decrypt`, and without it `decrypt` of `@iceroot-network/sdk/tauri/keystore` is refused with `SdkNotInitialized`. `net.keys.fromKeystore` opens accounts without the phrase entering the page and needs nothing more.
- **`examples/vite-react-wallet`**: create or restore, a keystore-encrypted phrase, balance, send, vote in each mode with a review screen, and sign in, tested against a local devnet.
- **`examples/tauri-plugin`**: a Tauri app on the plugin: connect, a keystore with the desktop preset, an account opened from it, a signed message.
- **Memory:** the package wipes the WebAssembly stack after every call into the module, so keys and entropy do not stay in its memory.
- **Size:** the module is about 416 KB gzipped.
