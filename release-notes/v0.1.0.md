The first release. The interfaces below changed shortly before it; code written against earlier development builds needs these changes.

- **No fee from the node's statistics.** `Draft.build(chain, request, facts)` takes no fee statistics any more, the builders of `net.build` never read `/node/fees`, and `FeeSource` is `"floor"` or `"explicit"` (the `"node-statistics"` source is gone). `net.fees.statistics()` stays, for display. A serialized draft whose fee source names anything other than `"floor"` reads as `"explicit"`.
- **No floor without an enabled fee table.** Where the milestone in force has no enabled dynamic fee table, the node's pool applies settings of its own, so there is no floor: `rules.fees.floorAvailable` is `false` (it now says whether the floor is in force at that height), `draft.summary.fee.floor` is absent, and fee `"minimum"` and `{ multiplierBasisPoints }` throw `FeeUnavailable`. Such a network needs an exact `bigint` fee. A draft never carries a zero fee labelled as the floor.
- **Headers for a relay behind a proxy.** `connect(profile, { headers })` sends extra headers with every request, for a relay that asks for a token. The Rust SDK of the same version adds the same to its HTTP client (`HttpOptions::headers`), so a Rust backend reaches the same relay.
- **`net.watch`.** Stopping a watch, by the function it returns or by its `signal`, now also removes its listener from that signal. The documentation states its limits: one `block` event per poll for the latest block, and at most 50 new transactions per poll for the watched address.

It also carries the vote selection library, the keystore, ownership proofs and an example wallet:

- **`@iceroot-network/sdk/vote`**: select a vote in four modes (Diversity, Reliability, Maximum Rewards, Support Newcomers), sampled per account and reproducible, then `split`, `check` and `validateVote`; `VoteSnapshot.fromNode` builds the snapshot from the node client. Validators a node refuses votes for are left out.
- **`@iceroot-network/sdk/keystore`**: `encrypt`, `decrypt`, `inspect`, `changePassword` and `reencrypt` for a versioned encrypted format of recovery-phrase entropy (Argon2id and XChaCha20-Poly1305), with presets for desktop, mobile and web. Password bytes are wiped after use.
- **`@iceroot-network/sdk/ownership`**: build, sign and verify version 1 ownership proofs of Solar addresses, as the legacy signer makes them, for claims.
- **`Keys.fromKeystore` and `net.keys.fromKeystore`**: an account opened straight from a keystore, decrypted and derived inside the SDK, so the phrase never reaches JavaScript.
- **`@iceroot-network/sdk/tauri`** (with `/tauri/vote`, `/tauri/keystore` and `/tauri/ownership`): the same interface for Tauri apps, backed by the Rust SDK's plugin `tauri-plugin-iceroot` of the same version. Keys, signing, the keystore and every request to the node run in the plugin; the page loads no WebAssembly and needs no content security policy change. The calls that compute return promises, so an app written with `await` on every SDK call runs on either entry, and `init()` checks that the plugin is of the package's release. Checked on Linux with the SDK's test suites and the devnet scenario; the plugin builds for Android, and macOS and iOS builds need a Mac.
- **`examples/vite-react-wallet`**: create or restore, a keystore-encrypted phrase, balance, send, vote in each mode with a review screen, and sign in, tested against a local devnet.
- **`examples/tauri-plugin`**: a Tauri app on the plugin: connect, a keystore with the desktop preset, an account opened from it, a signed message.
- **Memory:** the package wipes the WebAssembly stack after every call into the module, so keys and entropy do not stay in its memory.
- **Size:** the module is about 416 KB gzipped.
